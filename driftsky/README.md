# Driftsky

Weather for your desktop. Snow, rain, sakura, leaves, fireflies and starfall fall over your screen,
settle on your windows and tumble off when you move them. Plus wallpapers to match.
$9 for 1 computer or $15 for 5, paid once.

This monorepo holds everything needed to sell and ship it:

| Path | What |
| --- | --- |
| `packages/engine` | The weather engine (TypeScript, canvas 2D). Used by the desktop overlay and the website demos. |
| `apps/desktop` | The app: Electron menu-bar app for macOS 14+ and Windows 10/11. |
| `apps/web` | The website (React + Vite) and the license server (Express + SQLite): checkout, keys, activation, downloads, updates. |
| `assets` | Original wallpapers (generated by `tools/wallpapers`) and icons. |

## How it works

**Desktop app.** One transparent, click-through, always-on-top window per display draws the
weather. About 30 times a second the main process reads where every app window is (macOS:
`CGWindowListCopyWindowInfo`; Windows: `EnumWindows` + DWM frame bounds; both through
[koffi](https://koffi.dev), so there is no native build step) and sends each overlay the windows on
its display, the Dock/taskbar strip and the pointer. The engine treats the visible top edge of each
window as ground:

- **Snow** builds a height field along each window top, the Dock and the bottom of the screen. Move a
  window faster than ~45 px/s and the snow slides and flies off in clumps that land elsewhere; narrow
  a window and what's past the edge drops; close it and everything falls.
- **Rain** splashes on window tops, with lightning now and then.
- **Sakura** petals rest on windows for a while, then fade.
- **Leaves** pile up and scatter when the pointer sweeps through them.
- **Fireflies** wander and circle the pointer when it stays still.
- **Starfall** meteors burst into sparks on windows.

Snow never piles on a part of a window hidden behind another. Clicks always go through. On battery
the effect halves and drops to 30 fps. It pauses when a full-screen app covers a display, when the
screen locks and during sleep.

The menu-bar menu switches effects, wallpaper, amount and, on macOS, "Behind windows" (desktop
level, under your apps; Windows has no clean equivalent, so the option isn't offered there). The Settings window has Effects (live previews), Wallpapers (set on every screen),
License (activate, show/copy, remove from this computer, upgrade 1→5), Settings (open at login,
battery saver, pause for full screen, auto-update) and About (updates). First launch walks through
welcome → paste key (or a one-minute preview, or buy) → pick the weather.

**License server.** Checkout is Stripe Checkout (adaptive local pricing, promotion-consent for a
one-time 20%-off email if someone leaves). The signed webhook issues a key such as
`DRIFT-7KQ2-M9XA-...` and emails it; the thank-you page shows it too. The app activates with the key
plus a SHA-256 of the computer's hardware ID, which the server HMACs again before storing. Seats are
enforced in a transaction. Refunds and disputes turn keys off. The app checks in daily and keeps
working offline for 30 days.

**Updates.** `GET /api/app?platform=mac|windows` returns `{latest, minimum, url, sha256}` from
`releases.json`. The app downloads the new build, checks the SHA-256 and opens the installer.

## Running it locally

Requires Node 22.5+ (uses the built-in `node:sqlite`).

```bash
cd driftsky
npm install

# website + license server on http://localhost:5173 (mock payments, emails stored in a local outbox)
npm run dev:web

# desktop app against the local server
DRIFTSKY_API=http://localhost:5173 DRIFTSKY_SITE=http://localhost:5173 npm run dev:desktop
```

In dev, "Buy" goes to a test checkout page (no card). Emails are listed at
`http://localhost:5173/dev/outbox`.

## Tests

```bash
npm run test -w @driftsky/engine        # engine: physics, piles, occlusion, every effect, perf
npm run test -w @driftsky/web           # server: checkout, webhooks, activation, seats, downloads
npm run test -w @driftsky/desktop       # app: store, license manager, menu, geometry, updater, FFI signatures
npm run e2e  -w @driftsky/web           # website end to end in Chromium, desktop + phone, against a production build
npm run e2e  -w @driftsky/desktop       # the real Electron app under Xvfb against the real license server
```

`DRIFTSKY_*` environment overrides (API origin, fake windows, device ID, preview length, logs) only
work in development builds; a packaged app ignores them. The desktop e2e suite uses
`DRIFTSKY_FAKE_WINDOWS` (a JSON window list it rewrites to "drag"
windows) because there are no real app windows in CI. The macOS and Windows window readers are
covered by signature checks only; run the app on a real Mac/PC before release (see below).

## Configuration (license server)

Copy `apps/web/.env.example`. In production you need at least:

| Variable | |
| --- | --- |
| `NODE_ENV=production` | |
| `PUBLIC_URL` | e.g. `https://driftsky.app` (used in redirects and emails) |
| `DEVICE_SALT` | long random string; keep it forever (changing it detaches every computer) |
| `PAYMENTS=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | webhook endpoint: `POST /api/stripe/webhook`, events `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, `charge.refunded`, `charge.dispute.created` |
| `MAIL=resend`, `RESEND_API_KEY`, `MAIL_FROM` | key emails |
| `DATABASE_PATH` | SQLite file on a persistent disk |
| `RELEASES_PATH` | `releases.json` (see `apps/web/releases.example.json`); re-read on change, no restart |
| `TRUST_PROXY=1` | behind a load balancer, so rate limits see real client IPs |
| `VITE_POSTHOG_KEY` (build time) | optional website analytics, loaded only after cookie consent |

Build and run: `npm run build -w @driftsky/web && npm start -w @driftsky/web`.

## Verification

Besides the automated suites, three independent agents exercised the product as users and
reviewers (website QA across four screen sizes against koiart.app, desktop QA including
performance and memory, and a code/security review). Everything they confirmed was fixed and covered
by a regression test. Known limits: the macOS/Windows window readers and wallpaper setters can only
be exercised on real hardware; the upgrade link carries the key in a URL (consider a short-lived
token); the Swift "installer" app that KoiArt ships isn't replicated (the site serves the DMG / setup
directly).

## Shipping the app

```bash
npm run dist:mac -w @driftsky/desktop   # on a Mac: universal DMG + zip in apps/desktop/release
npm run dist:win -w @driftsky/desktop   # on Windows: NSIS installer
```

Set `CSC_LINK`/`CSC_KEY_PASSWORD` to sign. For macOS set `notarize: true` in
`apps/desktop/electron-builder.yml` and provide `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and
`APPLE_TEAM_ID`. The app is a menu-bar app (`LSUIElement`). The first wallpaper change asks for
permission to control System Events. Then upload the files, compute `shasum -a 256`, and update
`releases.json`.

Before a release, check on real hardware: weather lands on real windows (including on a second
display and with a Retina/scaled display), dragging sheds snow, full-screen video pauses it, the
wallpaper changes on every screen, and "Behind windows" works.
